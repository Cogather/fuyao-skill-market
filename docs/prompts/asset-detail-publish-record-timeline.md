## 0. 角色与任务

你是一名前端工程师，负责改造本仓库（Vue 3 + TypeScript + Vite 的 Harness 管理工作台）中**资产详情页 →「发布记录」页签**的内容展示。

任务一句话概括：**把资产详情页「发布记录」页签里的记录列表，改成与「发布历史」页面视觉一致的竖向时间线卡片样式；数据继续使用提供的发布历史接口；页面上补一个「重新加载」按钮；对发布失败的记录提供重试按钮，调用提供的失败重试接口。**

不要从零设计页面，先阅读仓库里已有的参考实现（见第 6 节），在它的基础上对齐视觉与交互。

## 3. 接口契约（唯一数据源，来自后端提供）

### 3.1 查看进度（发布历史）

```
POST /api/harness/assets/publish/history
Content-Type: application/json

Body:
{
  "batchId": "uuid",        // 可选，查某次提交的完整结果
  "assetType": "SKILL",     // 可选
  "assetName": "xxx",       // 可选
  "operatorId": "工号",      // 可选
  "pageNum": 1,             // 可选，默认 1
  "pageSize": 20            // 可选
}
```

- 四个查询条件均可选、可组合。
- `assetType` 取值使用大写枚举：`AGENT` / `SKILL` / `COMMAND`。
- 响应 `records[]` 关键字段：

| 字段 | 说明 |
|---|---|
| `id` | 记录 ID（重试时作为 taskId 使用） |
| `publishStatus` | 进行中 / 发布成功 / 发布失败 |
| `errorMessage` | 失败原因 |
| `source` | 独立发布 / Extension发布（两种来源合并展示） |
| `targetOrgName` / `targetOrgCode` | 目标组织 |
| `operatorName` / `operatorId` | 发布人 |
| `assetType` / `assetName` / `assetVersion` | 资产三元组 |
| `createdAt` / `updatedAt` | 时间，格式 `yyyy-MM-dd HH:mm:ss` |

### 3.2 失败重试

```
POST /api/harness/assets/publish/{taskId}/retry?userId={工号}
```

- 只对「历史列表中状态=发布失败 且 source=独立发布」的记录提供重试按钮。
- `taskId` 取历史记录的 `id` 字段。
- 语义是**原地续跑**（已完成的环节不重复执行），无需重新填参数。

## 4. 逐元素映射（参考页样式 → 原子资产发布记录字段）

时间线卡片的每个位置，只能使用接口返回的字段，**接口没有的字段一律不伪造**：

| 参考页（Extension 发布历史）元素 | 原子资产「发布记录」对应实现 |
|---|---|
| 左侧时间线竖线 + 状态色圆点 | 保留。圆点颜色与 `publishStatus` 一致：发布成功=绿、发布失败=红、进行中=橙 |
| 版本徽标 `v0.2` | `record.assetVersion`（原样展示；若形如 `0.1.0` 需要补 `v` 前缀时，沿用组件里已有的版本展示规则，不要另造规则） |
| 灰色小胶囊标签 `Product` | `record.source`（`独立发布` / `Extension发布`），沿用参考页小胶囊的样式，不要新增枚举或做文案改写 |
| 加粗资产名 | `record.assetName` |
| 右上角状态胶囊（成功/失败） | `record.publishStatus`（进行中 / 发布成功 / 发布失败），绿/红/橙三色与状态一一对应，右对齐 |
| 一行灰色描述 | **该接口不返回描述，省略这一行**（不要用其它字段凑数） |
| 浅红色失败原因块（前缀「失败原因」） | `record.errorMessage`，仅当 `publishStatus === '发布失败'` 且 `errorMessage` 非空时显示 |
| 「◆ 内部结构（N 项）」+ 芯片行 | **原子资产历史记录没有内部结构，整块隐藏**（不要显示空的「内部结构（0 项）」） |
| 底部元信息行：`用户：x（工号）` `时间：xxx` `组织：xxx` | `用户：{operatorName}（{operatorId}）`、`时间：{createdAt}`、`组织：{targetOrgName}（{targetOrgCode}）`；缺失字段用 `—` 占位 |
| 失败卡片内「↻ 重试发布」按钮 | 仅当 `publishStatus === '发布失败'` 且 `source === '独立发布'` 时显示；文案「↻ 重试发布」，点击调用 3.2 的 retry 接口 |
| 底部「已全部加载 · 共 N 条」/「加载更多（剩余 N 条）」 | 用响应的 `total` 与已加载条数计算，文案保持一致 |

### 样式细节（对齐图 4）
- 每条记录：左侧圆形节点 + 贯穿竖线；节点直径约 8–10px，实心圆，颜色同状态。
- 卡片：白底、1px 浅灰边框、约 8–10px 圆角，内边距约 14–16px，卡片之间纵向间距约 12px。
- 卡片头部：左对齐「版本 + 小标签 + 名称」，右对齐状态胶囊（`display:flex; justify-content:space-between`）。
- 状态胶囊：圆角胶囊，浅绿底深绿字 / 浅红底深红字 / 浅橙底橙字，字号小于正文。
- 卡片底部元信息：灰色小字（约 12px），多项之间横向排列、自动换行。
- 底部结束语：居中、灰色小字。
- 该区域在详情页里是**内嵌滚动容器**，不能撑破父容器高度（保持现在的内滚动行为）。

## 5. 交互要求

1. **首次进入**：切到「发布记录」页签时自动加载第 1 页（`pageNum=1`、`pageSize=20`），查询条件至少包含 `assetType`（大写）+ `assetName`。
2. **重新加载按钮**（R3）：
   - 位置：记录区标题行右侧（即图 1 红框内右上角现在「刷新」按钮的位置）。
   - 行为：重置到第 1 页重新查询，**保留当前的 `assetType` / `assetName` / `batchId` 条件**；不改变已选资产、不退出页签。
   - 状态：请求中禁用按钮并给出加载反馈；请求失败时展示可读的错误信息，并且**仍然可以再次点击重新加载**。
3. **重试按钮**（R4）：
   - 显示条件：`publishStatus === '发布失败' && source === '独立发布'`。
   - 点击后：按钮文案变为「重试中…」，期间禁用「重试发布」「重新加载」「加载更多」等会并发触发请求的按钮，避免重复提交。
   - 成功后：提示「重试任务已提交，请稍后刷新查看进度」，并重新加载第 1 页（刚重试的记录状态会变成「进行中」）。
   - 失败时：把后端返回的错误信息展示在页面的错误提示条中，不要静默失败。
   - `taskId` 必须取该条记录的 `id`，`userId` 使用当前登录用户工号（组件已有的 `userId` prop）。
4. **加载中 / 空数据 / 失败**：
   - 首次加载中：「正在加载发布记录…」。
   - 无数据：「暂无发布记录」。
   - 失败：错误提示条（浅红底）+「重新加载」按钮，两者都触发第 1 页重新查询。
5. **加载更多**：当已加载条数 < `total` 时显示「加载更多（剩余 N 条）」；点击后加载下一页并**追加**到现有列表，不覆盖已加载数据。
6. **状态值直用**：`进行中 / 发布成功 / 发布失败` 直接使用后端返回值渲染，不做二次映射或改写。

## 7. 约束与明确不做的事

1. **不要改动 Extension 链路**：`/extensions/history`、`/extensions/{id}/retry`、`ExtensionPublishPage.vue` 与 `LegacyExtensionPublishPage.vue` 的行为保持原样；Extension 详情页的「发布记录」页签也仍然走它自己的接口。
