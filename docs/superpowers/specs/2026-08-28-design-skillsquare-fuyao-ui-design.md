# `design-skillsquare-fuyao-ui` Skill 设计规格

## 背景

当前项目已经形成稳定的 UI 语言，但样式分散在全局 CSS、页面级 SCSS 和 Vue 单文件组件中，并混有历史覆盖与业务特例。需要把最终有效的设计判断提炼为可发现、可迁移、框架无关的 Codex skill，供其他 TypeScript 前端项目复用。

设计依据包括：

- `src/style.css` 的全局背景、基础色和排版设置；
- `src/style/UserMarketShell.scss` 的市场、热榜、筛选、卡片和管理页面样式；
- `src/views/HarnessManagementPage.vue` 与 `src/views/skill/SkillPlanningPage.vue` 的高密度工作台样式；
- `src/components/skill/SkillCard.vue` 的内容卡片模式；
- `docs/Codex_AI协同产品设计案例_AgentCenter_Skill市场.md` 中已经确认的视觉目标与设计原则；
- 对热榜、全部技能、评审中心和 Skill 规划页面的实际渲染核对。

## 目标

创建名为 `design-skillsquare-fuyao-ui` 的 skill，使 Codex 能够：

1. 在新建或改造前端界面时复用本项目的视觉气质和信息层级方法；
2. 适配任意前端框架、组件库和样式工具；
3. 优先映射目标项目已有 tokens 与组件约定；
4. 在缺少设计基础时提供框架无关的 CSS Variables 和 TypeScript tokens；
5. 根据页面任务选择合适的信息密度，而不是让所有页面长得完全相同；
6. 在实现后检查视觉一致性、响应式、可访问性和操作可达性。
7. 从原项目的业务页签中抽取可复用的布局、状态与交互结构，但不把业务实体、流程名称或领域假设带入其他项目。

## 非目标

- 不复制当前项目的大体量 SCSS 或历史选择器覆盖。
- 不绑定 Vue、React、Angular、Svelte 等框架。
- 不强制使用 Sass、CSS Modules、Tailwind 或任何组件库。
- 不复用 Skill 市场、Harness、部门评审等业务模型、文案、路由或类名。
- 不使用原项目业务页签名称为通用页面模式命名。
- 不要求目标项目替换已有品牌色、设计系统或工程结构。
- 不建设可发布的跨框架组件库。

### 文件职责

- `SKILL.md`：只保留触发条件、核心原则、适配流程、引用路由和完成检查，避免加载不相关细节。
- `design-language.md`：记录视觉气质、语义 tokens、排版、间距、圆角、阴影、动效、响应式和密度规则。
- `page-patterns.md`：记录内容发现、详情阅读、数据管理、判断辅助、流程编排、配置与关系六类通用页面骨架。
- `component-patterns.md`：记录导航、步骤器、主从面板、指标区、按钮、表单、卡片、表格、标签、弹窗、反馈和空状态的视觉与交互契约。
- `fuyao-theme.css`：使用 `--fy-*` 前缀提供可选 CSS Variables，避免污染目标项目命名空间。
- `fuyao-theme.ts`：提供无第三方依赖、带只读类型推断的可选 token 对象。
- `example.html`：用语义 HTML 展示完整视觉组合，仅作为适配参考，不作为固定 DOM 模板。
- `agents/openai.yaml`：提供与 skill 一致的界面名称和默认提示，不关闭隐式发现。

## 视觉内核

### 产品气质

专业、轻量、清晰、可信，具有适度 AI 产品感，但不呈现展示型科技大屏效果。装饰只服务于识别与氛围，复杂页面优先保证阅读、扫描和操作效率。

### 默认色彩语义

以下值是可适配的默认值，不是目标项目必须逐字复制的品牌规范：

| 角色     | 默认值                            | 用途                     |
| -------- | --------------------------------- | ------------------------ |
| 页面背景 | `#f2f7ff` → `#fbfcff` → `#ffffff` | 明亮中性底色与轻渐变     |
| 面板     | `#ffffff` / 半透明白              | 卡片、筛选和工作区       |
| 标题     | `#07172f` / `#15171d`             | 一级信息                 |
| 正文     | `#52647d` / `#667085`             | 描述与常规信息           |
| 弱文本   | `#94a3b8`                         | 占位、辅助说明、禁用信息 |
| 边框     | `#e2e8f0` / `#e9edf3`             | 信息边界                 |
| 主蓝     | `#2f7df6` / `#2563eb`             | 主操作、选中、焦点       |
| 辅助紫   | `#7552ff`                         | AI 属性、渐变与辅助识别  |
| 辅助青   | `#2ecdd3`                         | 渐变与轻量强调           |
| 成功     | `#16a34a` / `#22b07d`             | 完成、已发布、组织级     |
| 警告     | `#f59e0b`                         | 待处理与提醒             |
| 危险     | `#dc2626`                         | 删除、失败和高风险操作   |

目标项目已有品牌体系时，skill 按语义角色映射现有值；只有没有可用主题时才建议采用默认 tokens。

### 排版、间距与形状

- 优先使用目标项目字体；无既有规范时采用系统中文无衬线字体栈。
- 发现型 Hero 标题建议 `42–52px`，普通页面标题 `34–42px`，区块标题 `24–30px`，正文 `13–15px`，辅助信息 `10–12px`。
- 常用间距从 `4、6、8、10、12、14、16、18、24、28、32px` 中组合，通过关系而不是统一放大建立层级。
- 表单控件常用 `6–8px` 圆角，普通面板 `8–12px`，展示型指标卡 `18–22px`，胶囊控件使用完整圆角。
- 阴影保持低透明度；普通内容依赖边框，浮层和主操作才提高阴影强度。
- 状态切换、hover 和焦点反馈通常使用 `160–180ms`，不加入无业务意义动画。

## 页面模式

原项目页面仅作为视觉和交互样本。skill 中的页面模式按用户任务与信息关系命名，不出现原项目业务实体、页签名称、业务状态或角色假设。

### 内容发现型

使用舒展标题、关键指标、轻量渐变、搜索与卡片网格。首屏应尽快出现可浏览内容，装饰不能挤压主体。

### 详情阅读型

减少背景装饰，突出标题、元信息、版本关系和正文阅读层级。长内容支持清晰分段与稳定锚点。

### 数据管理型

压缩控件和表格间距，保持稳定列宽、表头层级、批量操作和关键操作可见。横向滚动时保护重要操作列。

### 判断辅助型

使用主从布局、待处理列表、证据摘要、维度指标、意见输入和历史记录组织需要比较与判断的任务。视觉重点是让依据、当前对象、状态和最终操作之间的关系清晰，不预设评分、审批或评审等具体业务。

### 流程编排型

使用步骤器、范围筛选、结构化表格、行内编辑、进度状态和批量操作承载分阶段的配置或计划任务。保持步骤状态、数据范围、校验错误和关键操作可见，不预设规划对象、组织层级或发布流程。

### 配置与关系型

通过步骤、分区、树形关系和明确确认反馈降低认知与操作风险。高风险变更说明影响范围和可恢复性。

## 组件契约

- 顶部导航：轻背景、清晰选中线或选中态；滚动后才增强玻璃与阴影。
- 步骤器：展示当前位置、已完成与待处理状态；步骤标签使用通用序号和任务名称，不耦合领域流程。
- 主从面板：列表选择与详情内容保持稳定空间关系；窄屏时转换为顺序布局，不隐藏当前上下文。
- 指标与判断区：摘要指标、维度信息、证据和意见保持分组，不用高饱和颜色代替层级。
- 主按钮：每个局部任务区仅保留一个主要视觉重心；次按钮使用浅底或描边。
- 表单：标签在控件上方，焦点使用主蓝边框与低透明外环，错误态使用稳定危险色。
- 卡片：名称、用途和质量信号优先；标签控制数量与饱和度；hover 仅轻微抬升。
- 表格：表头浅底、行分隔清晰、数值便于扫描；筛选、排序、空状态和分页归属明确。
- 标签：颜色表达语义而非装饰，同义状态必须同色。
- 弹窗：标题、内容、风险说明和操作区层级稳定；遮罩可轻度模糊背景。
- 反馈：成功、警告、错误、禁用和无权限状态必须给出原因或下一步。
- 空状态：说明为什么为空，并在存在合理动作时给出下一步。

## 调用与适配流程

1. 读取目标项目的技术栈、已有 tokens、组件约定、相关页面和用户任务。
2. 判断目标页面属于哪种页面模式以及所需信息密度。
3. 保留目标项目品牌与工程约定，将扶摇风格内核映射到现有语义角色。
4. 先确定导航、标题、筛选、主体和操作关系，再实现局部组件。
5. 仅在目标项目缺少主题基础且任务包含实现时，使用或改编附带 assets。
6. 完成后检查一致性、响应式、键盘焦点、对比度、长文本、滚动和关键操作可见性。

skill 提供设计建议时不自动写入文件；用户明确要求实现或改造时，才在目标项目范围内修改代码。

## 灵活性与冲突处理

- 目标项目已有品牌色：保留品牌色，把主操作、选中和焦点映射到其主色。
- 目标项目已有组件库：使用组件库公开的 theme/token 接口，不绕过其体系堆叠全局覆盖。
- 目标项目已有紧凑密度：保留合理密度，只修复层级、间距节奏和操作可达性。
- 原页面结构来自特定业务：只迁移可观察的布局关系、信息优先级、组件状态和交互反馈，再用目标项目术语重建内容。
- 视觉参考与可访问性冲突：优先对比度、焦点可见性、语义结构和可操作性。
- 无法获得完整页面上下文：明确假设，先提供可逆的最小设计方案，不发明业务规则。
- 用户只请求评审：输出问题、依据和建议，不擅自实现。

## 验证策略

本 skill 属于参考与模式型 skill，使用真实应用场景验证检索、迁移和边界判断，而不是匹配固定措辞。

### RED：无 skill 基线

在不加载新 skill 的独立上下文中运行四个场景并记录实际输出：

1. 为全新的 TypeScript 内容发现页建立视觉方案；
2. 为已有品牌 tokens 和组件库的管理后台迁移风格；
3. 为包含筛选、批量操作和横向滚动的高密度表格工作台设计界面。
4. 将一个包含主从任务、维度指标、意见输入和历史记录的领域页面迁移到完全不同的业务中。

重点观察是否出现：泛化蓝色后台、过度渐变或阴影、机械复制固定值、忽略现有设计系统、信息密度失衡、关键操作不可达、缺少响应式与状态规则。

### GREEN：加载 skill 复测

使用相同场景，验证输出是否：

- 正确识别页面任务和密度模式；
- 保留目标项目已有框架、品牌和组件约定；
- 应用专业、轻量、清晰、可信的视觉内核；
- 给出可执行而非抽象的 token、布局和组件建议；
- 处理响应式、焦点、状态、长文本、滚动和操作可达性；
- 不引入当前项目业务名词和类名。
- 能从业务页面中复用主从布局、步骤器、指标分组、筛选表格、行内编辑和固定操作等结构，而不复制其业务语义。

### REFACTOR

针对复测中真实出现的遗漏调整 skill。该 skill 不是纪律约束型 skill，因此不预设合理化表或大量禁止条款；使用正向输出契约和可观察判断标准塑造结果。

## 验收标准

- skill 名称严格为 `design-skillsquare-fuyao-ui`。
- YAML frontmatter 合法，description 以 `Use when...` 开头且只描述触发场景。
- `SKILL.md` 保持精简，详细信息通过清晰路由按需读取。
- 所有参考文件使用通用页面与组件语言，不绑定业务和框架。
- 原项目业务名称只允许出现在本设计规格的来源说明中，不出现在 skill 的 references、assets、示例文案或模式名称中。
- CSS 与 TypeScript assets 无第三方依赖、命名隔离且可独立采用。
- 示例完整展示视觉组合，但明确不是固定模板。
- `quick_validate.py` 通过，无占位符和无效引用。
- 四个验证场景在加载 skill 后均比无 skill 基线更稳定地满足设计目标。
- 最终 diff 不修改当前产品页面和既有业务代码。
