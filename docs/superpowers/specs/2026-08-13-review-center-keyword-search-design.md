# 评审中心待评审 Skill 关键字搜索设计

## 背景

“评审中心”的月度评审页面通过左侧任务列表展示待评审 Skill。现有列表支持评审状态、月度、业务维度、部门和排序筛选，但缺少按关键字定位 Skill 的能力。

本次在左侧任务列表上方新增搜索框，并在获取评审列表时传递 `keyword` 参数。搜索与现有筛选条件组合生效。

## 范围

本次只调整“评审中心”下的月度评审页面，不影响部门评审页签及其他 Skill 列表。

包含：

- 在左侧任务列表上方增加关键字搜索框和搜索按钮。
- 支持停止输入 300ms 后自动搜索。
- 支持按 Enter 或点击搜索按钮立即搜索。
- 支持清空关键字后恢复完整列表。
- 获取评审列表时增加 `keyword` 参数。
- Mock 数据源同步实现关键字过滤，保证本地开发行为与 HTTP 模式一致。

不包含：

- 将关键字同步到 URL。
- 保存或恢复用户上次输入的关键字。
- 修改后端搜索匹配规则。
- 为部门评审页签增加相同搜索能力。

## 页面与交互

搜索区位于左侧“评审任务”说明文字下方、任务卡片列表上方，即需求截图红框位置。搜索框占据可用宽度，右侧放置可点击的搜索按钮。

搜索框占位文案为“搜索待评审 Skill”。输入内容保留原始显示值，请求前去除首尾空格。

触发规则：

1. 用户输入发生变化后启动 300ms 防抖计时。
2. 300ms 内继续输入时，取消上一次计时并重新计时。
3. 300ms 内没有继续输入时，使用最新关键字发起查询。
4. 用户按 Enter 或点击搜索按钮时，取消尚未执行的防抖计时，并立即使用最新关键字查询。
5. 清空搜索框后，同样经过 300ms 自动查询；也可以按 Enter 或点击按钮立即恢复完整列表。
6. 如果即将提交的规范化关键字与最近一次已提交的关键字相同，不重复发起请求。

搜索按钮在列表请求进行中保持现有页面的加载反馈，不另行引入全局遮罩。按钮应有明确的可访问名称，搜索表单应允许 Enter 提交。

## 数据流

页面维护两个不同用途的状态：

- 输入值：与搜索框双向绑定，用于即时展示用户正在输入的内容。
- 已提交关键字：记录最近一次实际用于查询的规范化值，用于构造请求并避免重复请求。

查询流程如下：

1. 自动搜索、Enter 或按钮点击调用同一个提交函数。
2. 提交函数清理防抖计时器，并对输入值执行 `trim()`。
3. 规范化值没有变化时直接结束。
4. 更新已提交关键字，并通过现有重载入口重新获取任务列表。
5. 现有列表重载逻辑将页码恢复到第一页、清空旧任务并重置左侧滚动位置。
6. `syncReviewListFilterObj` 将 `keyword` 与用户、状态、月度、分类、部门和排序等现有条件一起组装。
7. `loadReviewCenterData` 将参数原样传给 `skillBaseService.getSkillReviewList(listParams)`；HTTP 请求因此携带 `keyword`。
8. 现有请求令牌机制继续负责防止较早返回的请求覆盖较新的搜索结果。

组件卸载时必须清理防抖计时器，避免卸载后触发查询。

## Mock 行为

Mock 数据源在分页和排序前按 `keyword` 过滤任务。匹配忽略大小写，至少覆盖现有任务模型中的：

- Skill 名称 `name`
- Skill 标识 `skillId`
- 发布人/负责人 `ownerName`

空白关键字不执行过滤。HTTP 模式的具体匹配字段由后端接口决定，前端只负责传参。

## 状态与异常处理

- 搜索请求复用现有 `reviewTaskLoading` 状态和错误提示。
- 搜索重载期间沿用现有防重复加载和请求令牌策略。
- 搜索结果为空时沿用任务列表现有空状态；若现有空状态不足以表达搜索无结果，仅补充与页面风格一致的空结果提示。
- 请求失败时保留输入值，便于用户重试；不回退已提交关键字。
- 按 Enter 或点击按钮触发后，先取消待执行的自动搜索，确保一次用户动作最多产生一次请求。

## 样式

搜索区宽度与左侧任务卡片列表一致，并保持与标题说明、首张任务卡片之间的现有纵向节奏。输入框和按钮沿用项目既有圆角、边框、蓝色主色和焦点态，不改变左侧栏宽度或右侧评审详情布局。

在窄视口下，搜索区仍保持单行；输入框优先伸缩，按钮保持可点击尺寸。搜索框获得键盘焦点时应有清晰焦点样式。

## 验收标准

- 搜索框出现在月度评审左侧任务列表上方指定位置。
- 停止输入 300ms 后，只发起一次评审列表请求。
- 按 Enter 或点击搜索按钮可以立即请求，不会在 300ms 后重复请求。
- 请求参数包含经过首尾空格清理的 `keyword`。
- 清空输入后，请求携带空关键字并恢复完整列表。
- 搜索会重置分页和左侧滚动位置，并可继续按现有无限滚动逻辑加载后续页。
- 关键字与状态、月度、业务维度、部门和排序筛选组合生效。
- 较早返回的请求不会覆盖较新的搜索结果。
- Mock 模式可按名称、Skill 标识和负责人进行不区分大小写的搜索。
- 部门评审页签及其他页面行为不受影响。
- TypeScript/Vue 构建和 ESLint 检查通过，且不存在未清理的防抖定时器。

## 验证策略

项目当前未配置自动化测试脚本，因此本次采用静态检查、构建检查和针对性交互验证：

- 检查请求参数组装，确认 `keyword` 进入 `getSkillReviewList`。
- 检查防抖与立即提交共用同一入口，且立即提交会取消计时器。
- 在 Mock 模式验证输入停止、Enter、按钮、清空和无结果五种路径。
- 验证新搜索会从第一页开始，滚动加载后续页仍携带相同关键字。
- 快速连续输入不同关键字，验证最终结果对应最新关键字。
- 运行 `npm run lint` 和 `npm run build`。
