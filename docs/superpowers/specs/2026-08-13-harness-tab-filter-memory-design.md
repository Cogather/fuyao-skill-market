# Harness 页签筛选记忆设计

## 背景

`/harness-management` 下的 Command 规划、Skill 规划、Agent 规划，以及配置管理下的场景管理、活动管理、部门权限配置，在切换页签时会销毁当前子组件。子组件再次挂载后恢复默认筛选范围，导致用户需要重复选择部门或产品。

本次改造只解决当前路由停留期间的筛选范围记忆，不持久化到浏览器存储，也不保留页面中的其他临时操作状态。

## 目标

- 每个相关页签独立记住自己最后一次确认的部门或产品筛选范围。
- 用户切回页签时恢复该页签自己的选择，不继承其他页签的选择。
- 离开 `/harness-management` 或刷新浏览器后清空记忆，重新使用页面默认值。
- 恢复选择时继续遵守当前用户的部门权限和当前可用产品范围。

## 范围

独立维护以下六份筛选快照：

1. Command 规划。
2. Skill 规划。
3. Agent 规划。
4. 配置管理／场景管理。
5. 配置管理／活动管理。
6. 配置管理／部门权限配置。

规划页签、场景管理和活动管理保存：

- 层级：`产品级` 或 `部门级`。
- 已确认的完整部门路径。
- 产品 ID 和产品名称；部门级选择时为空。

部门权限配置只保存已确认的完整部门路径。

以下内容不在本次记忆范围内：

- 表格分页、排序、关键字和其他业务筛选条件。
- 表格勾选项。
- 弹窗开关和弹窗表单内容。
- 未保存的场景或活动编辑内容。
- 配置管理当前选中的内部页签。

## 方案

### 状态所有权

由 `HarnessManagementPage` 持有当前路由生命周期内的筛选快照集合。快照以明确的页签 key 隔离，避免复用同一个规划组件时出现 Command、Skill、Agent 之间串值。

父页面不使用 Pinia、`localStorage` 或 `sessionStorage`。当路由组件卸载时，快照随组件内存自然释放，满足离开路由或刷新后恢复默认值的要求。

### 组件接口

筛选组件使用受控快照接口：

- 父页面通过 prop 传入当前页签的初始筛选快照。
- 子页面只在用户完成有效选择后发送快照更新事件。
- 快照中的数组在父子组件边界处复制，避免不同页签共享可变引用。

`HarnessConfigurationPage` 负责将配置管理的三份快照分别路由给场景、活动和部门权限面板，并把各面板的更新事件转发给 `HarnessManagementPage`。

### 更新时机

规划页、场景管理和活动管理在以下操作成功完成后更新快照：

- 用户切换产品级或部门级。
- 用户在部门级联选择器中点击“完成”或执行有效的默认恢复。
- 用户在产品下拉框中选择有效产品。

部门级联选择过程中尚未点击“完成”的临时路径不写入快照。产品级切换部门后，在产品列表加载并确定有效产品前，快照保留已确认的层级和部门路径，产品字段为空；产品选择完成后再补全产品字段。

部门权限配置在用户提交有效部门路径或恢复有效默认部门后更新快照。

### 恢复与校验

子组件初始化时优先尝试恢复传入快照：

1. 校验层级值是否为支持的层级。
2. 根据完整路径在当前可选部门树中查找部门，确保部门仍存在且仍在权限范围内。
3. 部门级快照通过校验后直接恢复并加载对应数据。
4. 产品级快照先恢复部门并加载该部门的产品列表，再按产品 ID 优先、产品名称兜底查找产品。
5. 产品仍有效时恢复该产品；产品失效时使用当前页面既有的产品默认策略。

如果部门路径无效或权限已变化，则整份快照不再用于恢复，页面执行原有默认筛选初始化。回退过程不绕过权限检查，也不显示额外错误提示。

### 未保存编辑

页签切换仍沿用现有组件销毁行为，本次不通过 `KeepAlive` 保存完整页面状态。因此，场景或活动中的未保存编辑不会因本次筛选记忆功能而被保留。现有部门切换确认逻辑保持不变。

## 数据流

1. 用户进入 `/harness-management`，父页面创建空的六页签快照集合。
2. 首次进入某页签时，子页面没有可用快照，执行原有默认选择。
3. 用户完成部门、层级或产品选择，子页面发出规范化快照。
4. 父页面仅更新该页签对应的快照。
5. 用户切走页签，子组件销毁；父页面中的快照继续存在。
6. 用户切回页签，新子组件收到该页签快照，校验并恢复选择和对应数据。
7. 用户离开路由或刷新页面，父页面销毁，所有快照清空。

## 验证策略

项目当前没有现成的组件测试框架。本次将把快照规范化、路径校验和产品恢复选择提取为无副作用的 TypeScript 辅助逻辑，并使用项目可执行的轻量测试入口先验证失败、再实现通过；同时运行现有 lint、类型检查和生产构建。

验证场景包括：

- Command、Skill、Agent 三个规划页签分别恢复自己的层级、部门和产品。
- 场景管理、活动管理、部门权限配置分别恢复自己的选择。
- 任意页签的更新不会覆盖其他页签快照。
- 部门级快照不会携带旧产品。
- 无权限或不存在的部门路径回退到默认选择。
- 不存在或已不属于当前部门的产品按页面原有策略回退。
- 离开路由或刷新后没有任何持久化筛选记忆。

## 验收标准

- 在六个目标页签之间反复切换，切回后均显示各自最后一次确认的有效部门或产品范围。
- 不同页签可同时保持不同选择，互不串值。
- 当前权限或产品数据变化后，不恢复失效选择，也不产生不可操作状态。
- 页面其他筛选、分页、弹窗和编辑状态的行为不因本次改造发生变化。
- 刷新浏览器或离开后重新进入 `/harness-management`，所有目标页签按原有默认逻辑初始化。
